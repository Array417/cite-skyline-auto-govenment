# AutoGovernment × Presidente 完整玩法設計

設計日期：2026-11-16，Asia/Hong_Kong。依據 [PRD](../PRD.md) 及 [接口盤點](PRESIDENTE_SETTINGS_AUDIT.md)。這是完整成品的建議玩法與整合設計；未驗證部分不是現有功能保證，也不是分階段交付方案。

玩法取捨與相容性風險另見 [決策紀錄](GAMEPLAY_DECISIONS.md)。使用者已確認 **1A、2A、3A、4B、5A、6A、7A**；以下依此定案。玩法確認不代表技術整合已通過。

## 1. 玩家扮演甚麼

玩家是具有實際行政權的國家元首，決定施政目標、人事、制度方向與重大取捨。政府會自主研究問題、提出法案、安排預算與執行工程；議會、法院、企業與市民按自身處境作出反應。

遊戲地圖及人口提供國家模擬的實體基礎。每一項政治決定都應有城市或制度結果：例如住屋政策改變供應及負擔，基建改變通勤與土地價值，徵地引起補償爭議，經濟與公平感影響選舉。

設計以執政元首開局；之後可以維持民主、協商改革、逐步集權，或面對落選與政權危機。政府運作不需要玩家逐項按施工工具或每次批准小額日常支出。

零人口新城依 D5A 先由臨時國家行政運作，人口及機關具備條件後首次選舉；「首屆民選政府」只適用已具備相應政治條件的開局，不能替零人口城市虛構選舉結果。

## 2. 與 Presidente 的分工

| 系統 | 在整合設計中的責任 |
| --- | --- |
| Cities: Skylines II | 真實人口、企業、土地、交通、建築、服務、城市財政及工程實體 |
| Presidente | 其現有政治、政黨、議會、選舉、法律、司法、民情及金融狀態；透過驗證過的原有流程執行操作 |
| AutoGovernment | 元首辦公室、prompt、雙提交模式、政策目標、政府 agents、自主建設規劃、跨系統工作及結果追蹤 |
| 共享本地 LLM | 理解政策文字、整理已驗證方案、表達內閣意見及解說事件；模擬規則與遊戲決定實際結果 |

每條政策保存同一份來源、目標及進度。政治系統批准不等於工程完工；工程工具成功亦不等於合法撥款。國庫、選票、股份、案件與工程結果各有唯一責任系統，避免兩個 Mod 重複計算。

Presidente 已有操作介面繼續可用；玩家在其頁面或原生工具手動改動後，政府重新讀取狀態與調整工作。未接通的功能須顯示原因，不能只在 AutoGovernment 畫面改文字冒充原有狀態已改變。

## 3. 開局設計

| Presidente 開局 | 整合後的定位 |
| --- | --- |
| 首屆民選政府 | 建議預設：已有選舉授權的執政者，開始施政並接受現行議會與司法制衡 |
| 臨時行政長官 | 臨時／過渡執政開局；保留實際授權來源。原有省級、總督與上級政府設定須先解決，不能只改稱總統就視為國家元首 |
| 帶領民眾上街 | 沿用 Presidente 的在野起點，不作預設執政體驗；未取得職位時不能使用國家行政權 |

新局先讀取既有制度、職位、黨派與財政，再設定國家名稱／元首稱呼、施政優先方向和自治授權。當原有制度不允許主權元首身份時，需在正式整合決策中解決其制度映射；開局畫面不能掩蓋此差異。

可用名稱、外觀與任命入口不等於可任意重設現有城市制度。完整相容方案未驗證前，不承諾將任何既有存檔一鍵轉換。

## 4. 日常核心循環

國情與民情變化 → 政府發現問題／元首輸入政策 → 部門提出方案與成本 → 建議或強制流程 → 授權、立法及撥款 → 施工與行政執行 → 社會、市場及司法反應 → 選舉與制度追責 → 下一輪施政。

玩家每次打開元首辦公室會見到目前主要問題、政府正在做甚麼、政策受阻原因與需要取捨的事項。即使不輸入指令，政府仍依現行國策運作。重大事件即時通知，其餘按施政報告整理，避免每項瑣事都彈出確認。

政策不必只是一個數值。可以是一組有共同目標的措施，例如「五年改善住屋」包含土地供應、住宅劃區、道路、水電、補償與財政安排，每項子工作分別記錄授權及完成狀態。

## 5. prompt 與兩個提交按鈕

例子：

> 五年內改善低收入住屋，優先發展河東，起一條跨河橋；盡量避免加稅，保障受徵地家庭，工程支出不得超過我指定的上限。

| 玩家操作 | 政府處理 | 可能結果 |
| --- | --- | --- |
| 提出建議 | 研究、比較方案、協商、提交必要法案與預算；可修訂目標或分配次序 | 通過、修訂、延後、部分採納、遭否決 |
| 強制命令 | 以玩家指定模式記錄行政意圖，優先安排；檢查現有權力、機構服從及資源。越權時記錄其範圍並產生對應後果 | 執行、拖延、抗命、司法審查、工程受阻或政治危機 |

兩種模式都可從相同文字建立政策，不需每次再按確認。模型不能替玩家升級為強制，部門亦不能自行把遭否決的建議改成越權命令。

命令可以很強硬，但不會創造金錢、改變地形限制或令所有機構永久服從。若指定河東但城市沒有可辨識的地點，先顯示待釐清，不能隨意選址拆屋。

## 6. 自主政府與 agents

所有部門共享一個輕量本地模型；各 agent 是職責、工作佇列與決策流程，不是每人載入一個模型。

| 部門職責 | 自主工作 |
| --- | --- |
| 政務協調 | 維持施政目標、排序工作、協調部門衝突、追蹤承諾及受阻政策 |
| 財政 | 收支預測、可負擔性、稅制與預算方案、法定撥款及持續維護負擔 |
| 土地與住屋 | 需求與空置分析、買地、劃區、供應、服務配套與徵地安排 |
| 交通與工程 | 路網瓶頸、道路、升級、橋隧及公共設施的選址、工程安排與完工核對 |
| 民生與社會服務 | 地區／群體需要、服務不足、住屋負擔、就業及抗議訴求的回應方案 |
| 經濟與市場 | 行業政策、企業及基金風險、基建影響與市場資料；不直接指定股價 |
| 法務與治安行政 | 合法性評估、案件與禁令追蹤、補償執行及治安資源；法院保留獨立裁判流程 |

政府可在既有授權、預算及法律內自行執行日常工作。需要新法律或追加撥款時，自行走制度流程並回報結果。超出目標或無有效授權的工作保持受阻，不能用自動化掩蓋越權。

依 D3A，政府不得自行選擇越權、頒緊急權或重大集權措施；這些由玩家決定。依 D4B，在任玩家可手動接管，越權工程記錄其決定、真實支出及事後司法／政治後果。此權限不延伸至離任後繼續使用國庫或公共工程工具。

玩家可暫停自治、取消未執行工作、指定優先次序與支出上限，或手動接管。暫停自治不等於暫停整個遊戲；已完成工程及正在運作的社會仍存在。

## 7. 完整玩法模組

| 模組 | 玩家做甚麼 | 政府與社會如何回應 |
| --- | --- | --- |
| 國情與民意 | 閱讀地區、收入階層、行業及不同人群的需要；追問政策成效 | 使用真實統計及已標示估算；區分支持率、服務滿意、信任、恐懼與私人不滿 |
| 人事與內閣 | 任命、更換或要求官員辭職，選擇能力、立場與忠誠的取捨 | 能力影響執行，派系與利益影響協作；任命按原有制度及成本處理 |
| 國策與承諾 | 設定住屋、就業、環境、交通、福利及財政目標 | 拆成可行措施、持續評估、回報承諾達成／部分達成／失敗及原因 |
| 土地與城市發展 | 指定發展區及用途、保護區、徵地與補償方向 | 自主買地、劃住宅／商業／工業區、配套服務，核對實際供需及土地狀態 |
| 道路與公共工程 | 要求解決交通、建橋、隧道、升級道路及增設設施 | 比較路線、造價、坡度、連通、拆遷、工期及維護；失敗分段停止並回報 |
| 稅收與財政 | 選擇加減稅、福利、服務預算與大型投資的取捨 | 依原有財政程序處理，資金不足提出縮減、延後或其他合法融資方案，不憑空完工 |
| 議會與法律 | 提交法案、接受修訂、協商支持或嘗試越權 | 政黨及議員按立場、選區與利益表決，法律生效後才改規則 |
| 選舉與問責 | 制定競選方向、履行承諾、依法改革制度或走向限制競爭 | 生活變化、施政、公平感、事件及參與影響選票；票數、投票率及議席可追溯 |
| 社會抗議 | 回應請願、協商訴求、修改政策、維持秩序或採取強硬措施 | 出現具原因、地點、組織與訴求的抱怨、示威、遊行、罷工及可能暴動 |
| 股票與金融 | 觀察政策對企業的影響，制定基金、產業、國有化／私有化等已支援政策 | 盈利、成本、交通、勞動力與政治風險影響市場；交易、股息及資產變動各有對手方 |
| 行政司法 | 面對徵地、行政命令及工程禁令，選擇執行、上訴或抗命 | 聆訊、補償、暫停工程與上訴產生實際效果，抗命另有制度後果 |
| 民刑事司法 | 安排法院與法律援助資源，在制度容許下任命或特赦 | 調查、起訴、抗辯、審判、量刑、賠償及上訴按案件與證據進行 |
| 治安與利益衝突 | 處理治安資源、監管、人事與承包商關係 | 原有犯罪、利益網絡及司法模型可影響政府工作；增加資源不保證零犯罪 |
| 集權與獨裁 | 使用緊急權、改任命制度、繞過議會、限制政治活動及干預機構 | 制衡、服從、恐懼、資訊品質、貪腐、抵抗與統治聯盟關係隨處境變化 |
| 長期國家運作 | 跨任期施政、應對經濟或政治危機，調整或撤銷舊政策 | 國家、工程、公司、案件、債務及民情歷史持續存在；離任不會令世界重置 |

這些是完整產品的整合玩法要求，不代表表內每個操作已由目前接口支援。既有 Presidente 模型負責的領域優先沿用；不足項目需按 PRD 的整合／部分整合／自建決策補足，不能另建一套互相矛盾的法律、票數或帳目。

依 D6A，股票範圍為政府基金、企業市場與政策效果，不新增元首私人投資帳戶。依 D7A，玩家採情報視角；未知的私人不滿或機構忠誠不能直接展示為全知真值，報告需標示來源與可信度。

## 8. 民情如何自然形成行為

因素包括可支配收入、住屋負擔、失業、通勤、服務可達性、污染、治安、補償、公平感、政治參與、信任及歷史承諾。差異按受損群體、地區、程度及持續時間計算；並非所有數字都要相同，亦不宣稱已模擬所有現實因素。

例如，全城平均收入上升，但河西租戶被迫遷、租金與通勤成本惡化，仍可組織抗議；河東業主可能支持同一工程。投資者因地價與企業預期受益，亦不代表低收入家庭同步受益。

抱怨可經政策回應化解，也可因長期忽略、組織動員、信任下降或衝突事件而升級。和平示威不必然演變暴動；強硬命令亦不必然立即令全民反抗。成品須在地圖看見遊行與街頭事件，不能只顯示新聞文字。

壓制可能令公開抗議減少，同時使私人不滿、恐懼、地下活動或假報告增加。因此政府畫面會區分已知資料、估算、情報可信度與實際可觀察行為。

## 9. 民主、強制與獨裁的關係

民主政府可以使用行政命令；獨裁政府亦可能遇到官員拖延、法院反對、資金不足或地方抗命。兩個按鈕決定本次政策的提交方式，政體由多項制度及權力關係決定。

至少追蹤行政集中、議會制衡、司法獨立、選舉競爭、媒體／公民空間與機構服從。合法性、忠誠、恐懼與實際能力分開，避免只靠「獨裁分數」控制一切。

玩家可透過任命、制度改革、緊急權與政治操作逐步集中權力，也可撤回措施、恢復競爭、協商或交接。各路線都有施政及社會後果，不預設只要獨裁就一定有效或一定立即崩潰。

## 10. 一條跨系統政策的完整例子

以「河東新市鎮＋跨河橋＋保障受徵地居民」為例：

1. 政府讀取住屋需求、地形、現有路網、可購土地、財政與居民處境。
2. 部門提出不同規模或路線，附上估算、受益／受損群體及所需法律與撥款。
3. 提出建議時走協商及議會；強制命令則記錄行政權力及可能越權部分，安排相關機構回應。
4. 取得有效授權與資源後，買地、補償、劃區、建橋、連路及配套服務，各自核對真實結果。
5. 受影響居民可以協商、示威或起訴。若有禁令，正常執行流程暫停相關工段；政府另下抗命決定時才進入相應制度後果，不能背景偷偷續建。
6. 市場先反映預期；落成後再按實際通勤、企業成本與供應改變更新，不重複計算同一效果。
7. 政策報告追蹤支出、供應、通勤、補償、群體利益、訴訟與承諾，最後影響支持及選舉。

成功可能是住屋與交通改善但財政承壓；部分成功可能是橋落成、住屋不足；失敗可能是資金不足或禁令受阻。報告應保留真實取捨，不只顯示完成百分比。

每條指令顯示原文、模式、負責部門、來源資料、成本估算、目前狀態及原因。玩家能追問「點解唔起橋？」「邊個群體反對？」「承諾做到幾多？」；回答必須來自可追溯紀錄。

設定頁分開遊戲偏好、自治授權及制度規則。犯罪強度等玩家選項不自動變成元首政策；政府不能為了改善政績偷偷調低事件強度、改已讀旗標或啟用除錯生成工具。

## 12. 任期、離任與長期目標

整合模式按 Presidente 實際可讀及可執行的任期、選制與日程運作，不另起一套互相矛盾的選舉。新局制度選擇與改革需有有效映射，不能預填未驗證的年數。

玩家依 D1A 跟隨同一人物／政治身份。落選後按制度正式交接、被罷免或離任時，失去相應行政權並轉入在野玩法；可追蹤政績、提出政綱、爭取支持、依法參選，勝出並完成就任後恢復權力。無行政職權時停用元首強制命令及動用國家資源的操作；prompt 轉為在野政治活動，不再直接指揮部門。

正常選舉與制度容許的提前選舉均可成為復權機會；提前選舉由有權機關依法啟動，在野玩家不能直接強制觸發。勝敗由實際支持、選票及制度決定，不保證復權成功。已授權工作由現政府依法承接或修改，前任未授權命令不能冒充新政府執行，所有變更保留記錄。完整身份與交接流程尚需驗證，不能只交付離任後觀看模式。

長期目標以住屋、就業、財政、公共服務、公平、制度及承諾等多維結果呈現。任期報告展示誰受益、誰承擔成本、哪些目標未達到；沒有單一幸福度可以代表所有人或直接判定國家成功。

## 13. 模型、失敗與存檔體驗

模型負責有限語意與解說，政策、選票、法律、金錢與工程由可測試規則及遊戲決定。模型無法理解時顯示待釐清，不能將不支援要求誤轉成調稅等操作。

模型忙碌或中斷時，已授權的基本自治仍繼續；玩家可用有限政策模板。指令、預算、工程、案件、任期、歷史與隨機狀態隨存檔保留，重載不能重複撥款或執行舊推理。

缺少 Presidente 或版本不相容時，顯示受影響能力並停止相關寫入，保留自有資料。不能靜默把原有政治存檔改成另一套自建世界。
