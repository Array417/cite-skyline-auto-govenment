### 可用作擴充的公開結構

以下由 public 內容組件 metadata 確認型別與簽章，尚未完成所有回呼的遊戲內效果測試：

| 入口 | 已確認的結構 | 適用方向 |
| --- | --- | --- |
| `LegislativeCatalogue.All` | 政策目錄；各 Lever 有 Id、Sector、Min／Max／Step、名稱與顯示回呼、以 World 為參數的 Read／Write | 建立實際支援的政策能力目錄，按原有範圍驗證參數，不讓 LLM 發明欄位 |
| `LegislationSystem` | 建立草案、設定內容／措施、提出法案、讀取狀態及撤回 | 建議提交與立法流程；寫入及存檔需實測 |
| `StandingSystem.ProvideLaws`／`LawProviders` | 自訂法律提供者；Prefix、Count、Get、Write、Blocked | 讓擴充自己的授權規則進入原有法律流程；注意前綴衝突及反註冊 |
| `StandingSystem.AfterDivision` | 公開表決後回呼清單 | 更新政策執行記錄與等待中的政府工作；確認參數含義、呼叫時機及重載去重 |
| `StandingSystem.MoodModifiers` | 群體民情修正回呼清單 | 在有因果與存檔來源的情況下表達擴充新增的施政後果；不覆蓋原有群體民意 |
| `StandingSystem.UrgentDecree`／`WriteLaw` 等 | 存在相關公開方法 | 強制路線的候選，仍需確認授權、制度流程及實際後果；方法名不足以證明可任意強制任何政策 |

這些證據支持優先做獨立 extension，而不是複製原 Mod。它們不是原作者的穩定版本承諾；擴充必須檢查 public 內容識別與簽章，只操作經驗證的能力。載入／卸載時只移除自己加入的回呼，避免重複註冊或清空其他 Mod 的清單。

## 結論

### 開局身份與產品定位的相容性

使用者實際開局畫面提供「臨時行政長官」、「首屆民選政府」與「帶領民眾上街」。public metadata 確認 `StartKind.Classic`／`InPower`／`Movement`，以及 `MovementSystem.Start`、`StartOpen`、`ChooseStart(int,int,out string)` 等公開入口；尚未在各開局實測全部權限。畫面和接口訊息顯示臨時行政長官屬省級、由總督委任，不能直接當成主權國家元首。

- 開局身份用來設定既有權力與制度，不應取代本 Mod 的政策輸入和政府自治。
- 「首屆民選政府」是優先驗證執政元首流程的候選；「臨時行政長官」需確認上級政府權限及建國／制度轉換如何映射，不能只改名稱掩蓋權力差異。
- 「帶領民眾上街」屬在野起點，不符合預設直接執政的體驗；若玩家已在此路線，須如實辨識職位並限制無授權的國家行政操作，不強行覆寫成執政。
- 強制提交與獨裁程度分開：民選政府亦可發出命令；命令效果按權限、服從與資源處理。威權化須有可追蹤制度變化，不以選擇某個開局自動完成。
- 須查清 Presidente 原有自主政府決策與本 Mod agents 的責任邊界，避免雙重執行政策或出現兩套相反命令。

以上為整合設計約束與待驗證事項，尚未證明開局相容性已通過。

優先嘗試整合 Presidente，但目前不能承諾可直接控制它。公開資料足以確認它提供國家治理玩法，尚不足以確認穩定 API、公開源碼與重用授權。

依使用者最新要求，完整成品正式實作前先驗證政治資料與政策操作；若無合適接口，查找作者授權源碼，再自行實作不足部分。小型驗證不是交付版本。不要為尚未確認的接口建立整個政府核心，也不要在完成合理調查前重寫全部制度。

## 2. 開發前驗證方案

### A. 確認可測的實際版本

1. 檢查遊戲中目前 playset 與已安裝套件 metadata，記錄 Presidente 版本、依賴及支援遊戲版本。
2. 若沒有可用套件，使用公開文件繼續研究；列明仍需套件／遊戲測試，不假裝已測。付費 beta 不是預設依賴。
3. 建立另存測試城市，分開記錄原版、Presidente 單獨運行及與本 Mod 同用的基準。

### B. 接口調查

- 優先官方／作者文件、公開 API、合法取得套件的 metadata 與公開型別資訊；記錄實際可讀、可寫欄位及方法。
- 需要回答：可否讀取群體民意、選舉／議會狀態、法案、國庫、案件與市場？可否透過原有流程提交政策？
- 對每項能力記錄來源、權限、模擬更新時機、失敗方式及版本依賴。沒有能力就標示不支援。
- 反射或 patch 內部實作只有在確有必要時才評估，記錄脆弱性與版本限制；不直接把依賴私有欄位的方案當長期穩定 API。

### C. 最小整合實驗

在測試城市完成以下閉環，選擇實際接口支援的一項低影響政策：

1. 讀取並顯示一項政治／民意數據與其來源。
2. 透過雙按鈕保存玩家意圖；將可支援政策提交到 Presidente 原有流程。若它只支援一種流程，清楚標明另一種尚未接通。
3. 等待並讀回實際表決／政策／財政結果，核對是否只執行一次。
4. 存檔重載，再驗證政策狀態、資料歸屬與去重。
5. 測試外部 Mod 缺失或版本不支援時能否停用寫入而保留資料。

道路與橋樑施工另外驗證；讀到政治數據不能證明已可自動建設。

### D. 決策門檻

| 證據 | 決策 |
| --- | --- |
| 可維護接口能讀寫所需狀態，帳目與存檔可核對 | 整合相應領域；本 Mod 專注元首 prompt、自治與建設 |
| 只有部分接口通過 | 部分整合，明確劃分狀態與責任；未接通功能不得宣稱可用 |
| 無可用接口，但有適當授權源碼 | 評估合法參考／重用所需部分，保留來源與授權要求 |
| 源碼不可用、授權不明或維護成本不合適 | 依產品需求自建，記錄與 Presidente 的玩法和相容性差異 |
| 因網站／套件無法取得而不能確認 | 記錄未知及證據；繼續可獨立驗證的本體工作，不宣稱已證明無法整合 |

## 3. 源碼參考與其他 Mod

Presidente 尚無可確認源碼連結；不以作者聯絡方式作為已獲授權。若將來找到公開倉庫，先確認作者關聯、LICENSE、版本／commit，以及是否涵蓋所需資產。

[Network Tools 倉庫][S4] 公開道路編輯實作，並有 [MIT 授權檔][S5]，可作道路幾何、連接與施工研究候選。這項授權只適用該倉庫相應內容，不延伸到 Presidente 或遊戲資產；重用時保留適用通知並檢查子模組／個別檔案條件。尚未驗證其外部呼叫接口或與本 Mod 的相容性。

官方 Code Mod 說明確認可註冊自己的模擬系統、使用遊戲實體資料，並提醒更新可能影響 Mod [S6]。它提供本體開發方向，不能代替目前版本的 API 與遊戲內實測。
